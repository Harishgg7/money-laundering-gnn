## 3. Problem Statement
Money laundering in digital payment networks (UPI, wallets) hides as structural patterns across chains of accounts (e.g., layering, smurfing, mule-account routing). 
- **The flaw of current tech:** Traditional AML systems rely on rule-based thresholds (e.g., flag if > ₹50,000) or single-transaction machine learning. These ignore network structure, resulting in high false positives.
- **The compliance block:** Even highly accurate standard ML models are "black boxes" and cannot be deployed in regulated finance because banks and regulators require a human-readable audit trail explaining *why* a flag was raised.

## 4. The Solution
We are building a Graph Neural Network (GNN) that models accounts as nodes and transactions as edges. 
- The model will learn laundering patterns based on how money flows (multi-hop paths).
- It will include an explainability layer (GNNExplainer) to highlight the exact accounts and transactions behind each flag, turning a black box into a regulator-ready audit trail.

## 5. Architectural Pipeline (To Be Implemented)
The codebase must implement the following pipeline:
1. **Txn Graph Construction:** Ingest transaction logs and convert them into a directed graph (Nodes = Accounts, Edges = Transactions).
2. **GNN Layers (Message Passing):** Implement GNN layers (e.g., GraphSAGE, GCN, or GAT) to allow nodes to aggregate transaction and behavioral signals from their neighbors.
3. **Node Embeddings:** Generate mathematically rich embeddings for each node containing "neighbour info".
4. **Classifier (Prediction):** Pass embeddings through a Multi-Layer Perceptron (MLP) to output a Fraud Probability Score (0 to 1).
5. **Loss & Backpropagation:** Compare predictions to ground truth labels, calculate loss, and update model weights.
6. **Explainability Module:** Implement PyTorch Geometric's `GNNExplainer` or `Captum` to extract the most important sub-graph (nodes/edges) that contributed to a high fraud score.

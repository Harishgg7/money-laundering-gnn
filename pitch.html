The compliance gap

Today's AML systems face an impossible trade-off.

Money laundering hides as structure — layering, smurfing, mule routing — spread across chains of accounts. The tools banks use can't see structure, and the accurate ones can't explain themselves.

Status quo Rules & single-txn ML

“Flag if > ₹50,000” ignores the network entirely. In our test it flagged laundering with just 2.4% precision — 97.6% of alerts were false alarms, burying investigators. Accurate black-box models can't be deployed either: regulators require a human-readable reason for every flag.

Our approach Explainable GNN

Model accounts as nodes, transactions as edges. A GraphSAGE network learns how money flows across multiple hops, then GNNExplainer extracts the exact sub-graph of accounts and transactions behind each flag — turning a black box into an audit trail.

How it works

Six stages, transactions to audit trail.

Graph build

5M transaction logs → a directed account graph.

Message passing

GraphSAGE aggregates signals from each account's neighbours.

Embeddings

Each account gets a vector encoding its multi-hop context.

Classifier

An MLP head outputs a fraud probability, 0 → 1.

Focal loss

Backprop weighted for the ~80:1 imbalance.

Explain

GNNExplainer surfaces the sub-graph behind the flag.

Where it stands

An honest prototype, with a clear road ahead.

Current limits

  • Recall is 27% — precision-first by design, but launderers are still missed.
  • Explanations skew toward self-loop signals; ~1 in 5 top flags shows a rich multi-hop chain.
  • Trained on the HI-Small tier only, single run — no error bars yet.
  • Node-level labels (account illicit if in any laundering txn), not per-transaction.

Next steps

  • Temporal edge features to catch rapid layering bursts.
  • Scale to Medium/Large tiers with neighbour-sampled training.
  • Validate explanations against the dataset's labeled typologies.
  • Push recall with class-balanced sampling and deeper hops.

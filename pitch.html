Model & System Specifications

Technical evaluation, baseline comparisons, and operating threshold calibration on the IBM AML benchmark.

Why Graph Neural Networks for Anti-Money Laundering?

Traditional rule-based monitoring and tabular machine learning (MLP) evaluate accounts in isolation using static balances and local frequencies. Launderers deliberately structure transactions into small, normal-looking increments (“smurfing”). GraphSAGE learns directly from the multi-hop transaction network, sensing relational coordination across accounts that is invisible to feature-only models.

Model Architecture PR-AUC Precision Recall F1 Score Information Used
Rule-Based Filter (Amount > Limit) 0.021 2.4% 22.0% 0.044 Transaction amount threshold only (97.6% false alarms)
MLP Baseline (No Graph) 0.184 48.7% 17.8% 0.261 Account-level tabular features in isolation
GraphSAGE (TRACE) 0.342 (+86% lift) 57.0% 27.1% 0.368 Account features + 3-hop directed transaction network
Key Evaluation Finding: Both the MLP baseline and GraphSAGE utilize the exact same 11 account features. The performance gain (PR-AUC 0.184 → 0.342) isolates the pure empirical contribution of the relational transaction topology.

Operating Decision Threshold

Under severe class imbalance (~80:1 negative-to-positive ratio), default 0.5 probability thresholds fail. TRACE applies a validation-calibrated operating threshold of 0.378, maximizing F1 score while holding precision above 57% to prevent compliance officer alert fatigue.
